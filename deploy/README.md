# Deployment integration

Source stays in the existing `homemind-landingpage` workspace. There is no VPS clone, new application root or releases directory tree. Docker/Compose internal storage and flat OS config/state files implement the two slots. Follow the current plan/audit/report, retaining the historical pause checkpoint.

Actual audited architecture: Ubuntu 24.04.3 amd64, Docker 29.8.2, Compose 5.5.1, host Nginx/Certbot webroot. API 127.0.0.1:3000 and its database/networks/config/certificate are protected. Landing slots bind only 127.0.0.1:3100 and 3101, each 512 MiB/1 CPU. Static config in `server.audited.json` records actual runtime identities, health and protected hashes; `server.example.json` intentionally fails validation.

Operator-reviewed fixed wrappers install into `/usr/local/sbin/homemind-landingpage-*`; config into `/etc/homemind-landingpage.json` and `/etc/homemind-landingpage-compose.yml`. Flat root-only records `/var/lib/homemind-landingpage-*-release.json` plus Compose/env/server/adapter/proxy snapshots preserve immutable digest and configuration. State and outcome are atomic; lock is `/run/lock/homemind-landingpage.lock`. No project root is created. Initial baseline snapshot is `/var/lib/homemind-landingpage-bootstrap-20261002-proxy-snapshot`. System installation refuses different existing files, reconciling a partial identical install safely. The generated ignored operator payload is transport for initial reviewed code, never executed by Actions or the deploy identity.

`proxy-adapter.py` controls only the separate landing Nginx vhost. It validates route ownership and global syntax before/after writes, preserves API/default configuration, snapshots the complete app route, uses only graceful reload, restores before failure cleanup and rejects unrelated-domain snapshots. Certificate issuance is separate through existing Certbot webroot, own homemind.vn lineage. Timer/deploy hook are reused; renewal rehearsal targets only landing.

`bootstrap.sh` validates installed config/code/backend first, then installs a dedicated forced-command key and narrow sudo identity. No Docker group, arbitrary command or workflow-uploaded root script. SSH protocol only `deploy SHA sha256:DIGEST RUN_NUMBER` and `rollback-if SHA sha256:DIGEST RUN_NUMBER`. Argument/source/revision/platform/port/resource/runtime validation constrains root Docker access; it is not a general Docker privilege boundary.

The deploy job has packages:read, sends its short-lived `GITHUB_TOKEN` through SSH stdin, and root logs in using password-stdin in an app-only temporary root directory under `/run`. That directory is removed after pull. No permanent PAT or shared backend Docker auth configuration. Package must stay private and linked to this repository; build job verifies this. First private pull is verified after initial CI package publication and before any candidate or routing change. Ordinary container restart uses the already pulled immutable image. Manual operations requiring a new private pull need a fresh read credential through secure stdin, never argv or tracked files.

Pull/provenance and protected-backend checks precede touching the inactive slot. Candidate readiness/assets precede route switch; post-check failure restores snapshot, checks old landing/backend and leaves workflow failed. First deployment explicitly has no previous release. Stable Actions concurrency, app flock and high-watermark reject stale jobs; workflow checks main HEAD before SSH. Same current SHA/digest can be verified idempotently. Previous healthy slot drains at least 120 seconds before reuse. Removing its slot invalidates its rollback pointer even if the next candidate fails.

Manual/conditional rollback uses the retained previous container and archived configuration/snapshot, preserves freshness and never overwrites a newer current release. Metadata cleanup retains current/previous, three healthy and newest failed records, deletes only exact app-prefixed flat files after ownership/path checks. It does not prune Docker images/networks/volumes. Monitor disk usage; min-disk gate fails safely rather than global cleanup.

Local browser/image evidence is reused for unchanged source. Controller tests are isolated; actual private pull, main-triggered run, public browser, digest, backend and renewal are separate production evidence. Root passwords/keys/tokens and real env values never belong in Git, logs, command arguments or these docs.
